# 6주차 과제: 요청량과 HPA 기준 비교

**week6_sender는 요청을 보내고, week6_practice는 요청을 받습니다.** 발생기 화면의 요청량과 수신 저장소의 HPA 기준을 바꾸며 Pod 수를 비교합니다. 제출 기한과 형식은 LMS 공지를 따릅니다.

## 1. 요청량에 따른 Pod 변화 관찰

HPA 목표가 **Pod당 평균 50건/분**, 최소 1개·최대 5개인 기본 설정으로 시작합니다.

1. <http://localhost:8090>에서 프로젝트 검색을 선택하고 요청을 시작합니다.
2. 분당 요청량을 **40 → 120 → 220건**으로 바꿉니다.
3. 각 단계에서 최소 90초 관찰합니다. 아직 변하는 중이면 요청량과 준비된 Pod 수가 안정될 때까지 더 기다립니다.
4. <http://localhost:8080>의 실제 요청량, 현재·준비된 Pod 수, Pod당 평균, HPA 목표를 기록합니다.

| 발생기 설정 | 실제 최근 60초 요청 수 | 준비된 API Pod | Pod당 평균 | HPA 목표 |
| --- | --- | --- | --- | --- |
| 40건/분 | 직접 기록 | 직접 기록 | 직접 기록 | 50 |
| 120건/분 | 직접 기록 | 직접 기록 | 직접 기록 | 50 |
| 220건/분 | 직접 기록 | 직접 기록 | 직접 기록 | 50 |

설정값과 실측값을 구분합니다. 최근 60초 집계와 Pod 준비 시간이 있어 결과가 즉시 바뀌지 않습니다. health·대시보드 조회는 요청량 지표에 포함되지 않습니다.

## 2. HPA 기준 변경

**수신 프로젝트의 `week6/k8s/hpa.yaml`**에서 `averageValue: "50"`을 `averageValue: "75"`로 바꿉니다. `maxReplicas: 5`는 유지합니다. 발생기 프로젝트의 Compose 파일은 수정하지 않습니다.

`week6` 폴더의 PowerShell에서 실행합니다.

```powershell
function kubectl { minikube kubectl -- @args }
kubectl apply -f ./k8s/hpa.yaml
kubectl get hpa api
```

1. 발생기 요청량은 **220건/분**으로 유지합니다.
2. 대시보드의 목표가 **75건/분**으로 바뀌는지 확인합니다.
3. 축소 대기 시간과 Pod 준비 상태를 고려해 안정될 때까지 관찰합니다.
4. 같은 실제 요청량에서 목표 50과 75일 때의 Pod 수를 비교합니다.

| 비교 | 목표 50건/분 | 목표 75건/분 |
| --- | --- | --- |
| 실제 최근 60초 요청 수 | 직접 기록 | 직접 기록 |
| 준비된 API Pod 수 | 직접 기록 | 직접 기록 |
| Pod당 평균 | 직접 기록 | 직접 기록 |

이론적인 필요 Pod 수는 **전체 요청량 ÷ Pod당 목표를 올림**한 값입니다. 최소 1·최대 5 제한도 적용합니다. 계산값과 실측값을 비교하고, HPA 기준을 바꿨을 때 Pod 수가 달라지는 이유를 짧게 설명합니다. HPA 실습 중 `kubectl scale`로 개수를 강제 변경하지 않습니다.

## 제출

- 요청량 40·120·220 관찰 표와 대시보드 화면
- HPA 목표 50·75 비교 표와 변경한 `k8s/hpa.yaml`
- 결과를 설명한 짧은 글과 본인 **week6_practice** 저장소 링크

요청 발생기 코드는 제출할 필요가 없습니다. Pod 삭제·장애 복구·이미지 업데이트·롤백은 이번 과제의 필수 항목이 아닙니다. 인증서·키·토큰은 제출하거나 커밋하지 않습니다.
