# 6주차 추가 과제

본인 week6_practice 저장소에서 기본 실습을 끝낸 뒤 진행합니다. 제출 형식과 기한은 LMS 공지를 따릅니다.

## 요청량과 자동 확장 비교

1. 요청 발생기를 40 → 120 → 220건/분으로 조절합니다.
2. 각 단계에서 최소 90초 관찰하고 최근 60초 요청 수, 목표·준비된 Pod 수를 기록합니다.
3. 요청을 중지하고 Pod 수가 줄어드는 과정을 확인합니다.
4. 대시보드 조회와 health 확인이 확장 지표에 포함되지 않는 이유를 적습니다.

## 확장 기준 변경

1. HPA YAML의 averageValue를 **50 → 75**로 바꿉니다.
2. HPA 파일을 다시 적용합니다.
3. 220건/분으로 실행하고 변경 전후 Pod 수를 비교합니다.
4. 요청 수를 75로 나눈 뒤 올림한 값과 실제 결과를 비교합니다.

maxReplicas: 5는 유지합니다. HPA를 사용하는 동안 kubectl scale로 바꾼 복제 수는 HPA가 다시 조절할 수 있습니다.

## 복구 확인

요청이 들어오는 상태에서 API Pod 하나를 삭제하고 새 이름의 Pod가 준비되는 과정을 기록합니다. 요청 발생기의 실패 건수도 함께 확인합니다. 단일 Minikube 노드에서의 Pod 복구이며 실제 여러 서버의 장애 대응 시험과 구분합니다.

| 제출 항목 | 포함할 내용 |
|---|---|
| 기본 확장 | 40·120·220건/분의 대시보드와 HPA 상태 |
| 기준 변경 | 50·75 설정과 같은 요청량에서의 Pod 수 |
| 복구 | 삭제 전후 Pod 이름, 준비 상태, 요청 실패 여부 |
| 설명 | Deployment·Service·HPA 역할을 각각 한 문장 |
| 저장소 | 본인 저장소 링크와 최종 commit |

관찰 시간과 요청 발생기의 설정값을 적고, 실제 측정값이 설정값과 잠시 다른 이유를 설명합니다. 인증서·키·토큰은 제출하거나 커밋하지 않습니다.
